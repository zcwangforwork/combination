> 生成时间: 2026-07-30
> 项目: user_management (贴敷式胰岛素泵员工管理系统)
> 技术栈: Spring Boot 3.2.5 + JPA/Hibernate 6.4 + PostgreSQL + Vue 3
> 评审状态: /plan-eng-review 已完成，2 个用户决策 + 3 个直接结论

## 1. 架构决策

### 1.1 版本链模型: Option A - Document 稳定 + DocumentRevision 存历史

```
Document (当前状态，原地更新)
  id=42, title=..., version=v1.1, status=PUBLISHED
  effectiveDate=2026-07-30

DocumentRevision (历史快照，不可变)
  id=1, documentId=42, version=v1.0
    title/fileName/contentSnapshot/checksum
    publishedBy/publishedAt/changeLog
    supersedesRevId=null
  id=2, documentId=42, version=v1.1
    supersedesRevId=1

URL: /api/documents/42  -> 永远返回当前版本
     /api/documents/42/revisions -> [v1.0, v1.1]
```

### 1.2 Diff: 元数据级对比

对比 title/description/category/fileName/fileSize/fileType/checksum，返回变更字段列表。checksum 不同时标记 `contentChanged=true`。不解析 PDF/Word 内部。

### 1.3 Rollback: 非破坏性

回滚 = 创建新 PUBLISHED 版本（内容复制自目标 Revision），旧版本保留。版本号递增（v1.3 回滚到 v1.0 → 生成 v1.4，内容=v1.0）。

### 1.4 版本编号

`v{major}.{minor}`，首次发布 v1.0，后续自动递增 minor。major 手动触发（P2）。

### 1.5 状态机

```
                  publish (首次)
      DRAFT ──────────────────────> PUBLISHED
        │                              │
        │                              │ publish (新版本, 快照旧状态)
        │                              v
        │                           PUBLISHED (v1.1)
        │                              │
        │                              │ retire
        │                              v
        │                           OBSOLETE
        │
        │ (REVIEW 审批流为 P1, 本次留桩不实现)
        v
      REVIEW (枚举存在, 转换未实现)
```

### 1.6 Upload 行为变更

- **变更前**: upload 创建文档，立即可见
- **变更后**: upload 创建 DRAFT（status=DRAFT, version=null），需显式 publish 才上线
- **迁移**: 现有文档自动设为 v1.0 PUBLISHED, effectiveDate=createdAt

### 2.3 新增实体: DocumentRevision

```java
/**
 * 文档修订历史快照（不可变）
 *
 * 每次 publish 时创建一条快照，记录当时的完整状态（含 BLOB 副本）。
 * 用于版本历史查询、版本对比、回滚。
 *
 * 关系图:
 *   t_document_revision
 *      ├── document_id      -> t_document     (N:1)
 *      ├── published_by     -> t_user         (N:1)
 *      └── supersedes_rev_id -> t_document_revision (self, N:1, 前一版本)
 */
@Entity
@Table(name = "t_document_revision")
public class DocumentRevision {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "document_id", nullable = false)
    private Long documentId;

    @Column(nullable = false, length = 20)
    private String version;

    // 元数据快照
    @Column(nullable = false, length = 200)
    private String title;
    @Column(length = 1000)
    private String description;
    @Column(nullable = false, length = 255)
    private String fileName;
    @Column(nullable = false)
    private Long fileSize;
    @Column(nullable = false, length = 100)
    private String fileType;
    @Column(nullable = false, length = 20)
    private String fileExtension;

    // BLOB 快照（复用 DocumentFile 的 @Lob 模式）
    @Lob
    @Column(nullable = false)
    private byte[] contentSnapshot;

    @Column(nullable = false, length = 64)
    private String checksum;

    // 发布信息
    @Column(name = "published_by", nullable = false)
    private Long publishedById;
    @Column(nullable = false, updatable = false)
    private LocalDateTime publishedAt;

    // 生效/作废时间
    private LocalDateTime effectiveDate;
    private LocalDateTime obsoleteDate;

    // 变更说明
    @Column(length = 500)
    private String changeLog;

    // 前一版本（版本链）
    @Column(name = "supersedes_rev_id")
    private Long supersedesRevId;

    @PrePersist
    protected void onCreate() {
        publishedAt = LocalDateTime.now();
    }
    // ... getters/setters
}
```

### 4.2 publish 方法核心逻辑

```
publish(id, changeLog, user):
  1. doc = findById(id) or throw
  2. checkVisibility(doc, user)  -- ADMIN 或上传人
  3. 校验状态:
     - OBSOLETE -> throw "已作废，不能发布"
     - REVIEW -> throw "审核中，不能发布"
     - DRAFT 或 PUBLISHED -> 继续
  4. 计算新版本号:
     - doc.version == null -> "v1.0" (首次发布)
     - doc.version == "v1.0" -> "v1.1"
     - 解析 major.minor, minor++
  5. 获取当前 BLOB:
     - fileRepository.findByDocumentId(id) or throw
  6. 创建 DocumentRevision 快照:
     - version = doc.version (旧版本号, 首次为 "v1.0" 待定)
     - title/fileName/fileSize/fileType/fileExtension = doc 当前值
     - contentSnapshot = file.content
     - checksum = file.checksum
     - publishedById = user.id
     - effectiveDate = doc.effectiveDate (旧的有效期)
     - changeLog = changeLog
     - supersedesRevId = 最后一条 Revision 的 id (或 null)
  7. 更新 Document:
     - version = 新版本号
     - status = PUBLISHED
     - effectiveDate = now
     - (不变更 obsoleteDate)
  8. 如果之前有 PUBLISHED 的 Revision, 设置其 obsoleteDate = now
  9. 保存 revision + doc
  10. return toDetailDto(doc)
```

### 4.3 diff 方法核心逻辑

```
diff(documentId, fromRevId, toRevId, user):
  1. doc = findById(documentId) or throw
  2. checkVisibility(doc, user)
  3. fromRev = revisionRepository.findById(fromRevId) or throw
  4. toRev = revisionRepository.findById(toRevId) or throw
  5. 校验 fromRev.documentId == toRev.documentId == documentId
  6. 逐字段对比:
     - title, description, fileName, fileSize, fileType, fileExtension
     - checksum (不同则 contentChanged=true)
  7. 返回 DocumentDiffDto { fromVersion, toVersion, changes[] }
```

### 4.4 rollback 方法核心逻辑

```
rollback(documentId, revId, user):
  1. doc = findById(documentId) or throw
  2. 校验 isAdmin(user)  -- 仅 ADMIN 可回滚
  3. targetRev = revisionRepository.findById(revId) or throw
  4. 校验 targetRev.documentId == documentId
  5. 校验 targetRev 不是当前版本 (通过 version 对比)
  6. 快照当前状态到新 Revision (同 publish 流程)
  7. 从 targetRev 复制回 Document + DocumentFile:
     - doc.title/description/fileName/fileSize/fileType/fileExtension = targetRev 值
     - file.content = targetRev.contentSnapshot
     - file.checksum = targetRev.checksum
  8. doc.version = 递增版本号
  9. doc.status = PUBLISHED
  10. doc.effectiveDate = now
  11. changeLog = "回滚至 v{target version}"
  12. 保存全部
  13. return toDetailDto(doc)
```

## 7. 数据迁移

### 7.1 迁移脚本 (Spring Boot ApplicationRunner)

```java
@Component
public class DocumentVersionMigrationRunner implements ApplicationRunner {

    @Autowired
    private DocumentRepository documentRepository;

    @Override
    @Transactional
    public void run(ApplicationArguments args) {
        // 查找所有 status 为 null 的文档（旧数据）
        List<Document> oldDocs = documentRepository.findByStatusIsNull();
        if (oldDocs.isEmpty()) return;

        for (Document doc : oldDocs) {
            doc.setVersion("v1.0");
            doc.setStatus(DocumentStatus.PUBLISHED);
            doc.setEffectiveDate(doc.getCreatedAt());
            // 可选: 创建初始 Revision 记录
        }
        documentRepository.saveAll(oldDocs);
    }
}
```

## 8. 并发安全 (Critical Gap 修复)

### 8.1 乐观锁

Document 实体添加 `@Version` 字段（`optimisticLockVersion`），JPA 自动处理并发冲突。两个用户同时 publish 同一文档时，后提交者触发 `OptimisticLockException`，Service 层捕获并转为友好错误。

### 8.2 publish 方法异常处理

```java
try {
    return publishInternal(id, changeLog, user);
} catch (OptimisticLockException e) {
    throw new IllegalStateException("文档正被其他人编辑，请刷新后重试", e);
}
```
