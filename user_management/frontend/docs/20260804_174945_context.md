**给出的优化建议（按合规优先级）：**

## P0 合规底线（不做过不了体系审核）

### 1. 审计日志（Audit Trail）- 最关键缺口
- 现状：只有 `updatedAt` 字段，无操作历史。`DocumentService.java:909` 注释提到"审计追踪"但实际未实现
- 法规依据：FDA 21 CFR Part 820 / ISO 13485 4.2.5 / 中国 GMP 要求所有体系文档变更可追溯（谁/何时/改了什么/为什么）
- 建议：建 `t_audit_log` 表（userId/action/entityType/entityId/before/after/ip/userAgent/timestamp），AOP 切面拦截所有写操作，不可删除、不可篡改

### 2. 电子签名（Electronic Signature）
- 现状：publish/编辑/删除仅靠 JWT 认证，无独立签名动作
- 法规依据：FDA 21 CFR Part 11 要求电子签名等同于手写签名，需签名者身份+签名时间+签名含义
- 建议：发布/作废/保密等级变更时弹窗要求二次密码确认，记录"签署人+签署时间+签署动作+签署含义"

### 3. 审批工作流（当前是桩）
- 现状：`DocumentStatus.java:22` REVIEW 状态注释明确写"P1 留桩不实现"
- 缺口：起草->审核->批准->发布 三级签署链缺失
- 建议：建 `t_document_approval` 表（documentId/approver/role/sequence/status/signedAt/comment），支持多级并行/串行审批

### 4. 数据完整性（ALCOA+）
- 现状：`DocumentRevision` 有 `checksum` 字段但读取时不校验
- 建议：下载时重算 checksum 比对，BLOB 字段加 `pgcrypto` 数字签名，检测篡改

## P1 运营效率

### 5. 文档有效期 & 复审提醒
- 缺口：`Document` 无 `nextReviewDate` 字段。ISO 13485 要求体系文档定期复审（通常 1-3 年）
- 建议：加 `reviewCycleDays` + `nextReviewDate`，定时任务扫描临期文档，仪表盘红色提醒

### 6. 培训记录 & 阅读确认
- 缺口：体系文档发布后，相关岗位人员须培训并签字确认已阅读，当前无机制
- 建议：建 `t_doc_acknowledgment`（documentId/userId/acknowledgedAt/signature），新版本发布时重置确认状态

### 7. 通知系统
- 缺口：无站内消息/邮件提醒。审批待办、复审到期、保密等级变更都靠用户主动查看
- 建议：建 `t_notification` 表 + WebSocket 推送，关键事件触发通知

### 8. 全文检索
- 现状：研发数据关键词只匹配 title/recordNo（`ResearchDataService.java:354`），文档无内容检索
- 建议：PostgreSQL `tsvector` + GIN 索引，PDF/Office 用 Apache Tika 提取文本，支持正文搜索

## P2 高级功能

### 9. 追溯矩阵（Traceability Matrix）
- 缺口：RISK 类型有 `traceToDesign` 字段但是自由文本，未结构化关联
- IEC 62304 要求：需求 -> 设计 -> 代码 -> 测试 -> 风险 全链路追溯
- 建议：研发数据记录之间建立关联表 `t_rd_link`（sourceId/targetId/linkType），前端可视化追溯图

### 10. CAPA 模块
- 缺口：FAILURE 故障记录无闭环机制。ISO 13485 要求纠正预防措施闭环
- 建议：新增 CAPA 记录类型或独立模块，关联 FAILURE/审计发现，跟踪根本原因/纠正措施/预防措施/验证/关闭

### 11. 变更影响评估
- 缺口：发布新版本无结构化变更影响分析
- 建议：publish 时强制填写变更申请单（变更原因/影响范围/受影响文档/培训需求/回归验证计划）

### 12. 文档预览
- 现状：必须下载才能查看，保密文档每次下载都留痕成本高
- 建议：PDF 用 pdf.js 在线预览，Office 用 LibreOffice 转 PDF，预览不触发下载审计

### 13. 受控分发 & 水印
- 缺口：保密文档下载后无追溯手段
- 建议：下载时动态叠加水印（用户名+IP+时间戳），PDF 加密限制打印/复制

### 14. 归档 & 销毁
- 缺口：OBSOLETE 文档永久保留在主表，无销毁流程
- 建议：加 `retentionDays` + `destroyDate`，到期自动转归档表，销毁需独立审批

### 15. 统计报表
- 现状：`DashboardController` 存在但功能基础
- 建议：体系审核常用指标 - 文档审批周期、超期复审数、CAPA 闭环率、培训完成率、审计日志异常告警

**最终建议优先级**：先做 1-3（审计日志 + 电子签名 + 审批工作流），这是体系审核的硬门槛。
